# MVS Virtual Instrument Laboratory — 가상 악기와 오케스트라 연구

> 음악을 생성하는 데서 멈추지 않고, 음악이 발생하는 물리적 세계를 설계한다.

- 제안일: 2026-11-27 (KST)
- 상태: 장기 연구 구상. 악기 엔진, 가상 오케스트라, AI 지휘 및 공간 음향은 미구현.
- 관련: [생체음향](BIOACOUSTICS.md), [가창](SINGING.md), [Voice Homage](VOICE_HOMAGE.md), [아키텍처](ARCHITECTURE.md).

## 1. 비전

인간의 발성기관을 악기의 하나로 본다면, 발성 시뮬레이션의 철학은 현악기, 관악기, 건반악기, 타악기 및 전자악기의 설계로 확장될 수 있다. MVS는 이러한 물리 모델링 합성(physical modeling synthesis)의 가능성을 탐구하며, 클래식 실내악과 오케스트라부터 팝, 록, 재즈, 전자음악까지 연주할 수 있는 가상 악기 연구 환경을 장기 목표로 제안한다.

핵심은 디퓨전 모델이 완성 음원을 한 번에 추정하거나 생성하는 방식이 아니라, 악기 모델과 연주 제어 데이터를 분리하여 소리를 계산하는 방식이다. AI는 선택적으로 작곡, 편곡, 연주 해석과 모델 설계를 보조할 수 있으나 소리 생성에 반드시 필요하지 않다. 물리 기반 음원 생성은 이미 존재하는 연구 분야이며, MVS의 독창적 목표는 생체음향·개인화 보컬·가상 악기·앙상블을 하나의 편집 가능한 음악 제작 흐름으로 통합하는 것이다. 기존 제품보다 우수하다는 검증 결과를 의미하지 않는다.

## 2. 악기 모델 카탈로그

| 계열 | 발음 원리와 주요 제어 | 수치 모델 후보 |
|---|---|---|
| 현악기 (바이올린, 비올라, 첼로, 콘트라베이스) | 현 길이·장력·선밀도·활 마찰·활 위치·압력, 몸체 공명 | 디지털 웨이브가이드, 비선형 마찰, 모달 공명 |
| 발현악기 (기타, 하프, 베이스) | 현의 초기 변위, 발현 위치, 감쇠, 브리지, 픽업 | 웨이브가이드, 모달 합성, 전기 회로 모델 |
| 목관악기 (플루트, 클라리넷, 오보에, 색소폰) | 공기 제트 또는 리드, 호흡압, 관 길이, 톤홀, 개구 방사 | 지연선/웨이브가이드, 리드·제트 비선형 모델 |
| 금관악기 (트럼펫, 호른, 트롬본, 튜바) | 입술 진동, 관의 임피던스, 밸브·슬라이드, 벨 | 입술 질량-스프링 모델과 관 모델 |
| 건반악기 (피아노) | 해머 충격, 현의 강성, 다현 결합, 공명판, 댐퍼와 페달 | 웨이브가이드, 모달 합성, 충격 모델 |
| 타악기 (팀파니, 드럼, 심벌, 마림바) | 막·판·막대의 진동, 타격 위치와 강도, 재질, 공명통 | 모달 합성, 질량-스프링, FDTD |
| 오르간 | 파이프와 공기 공급, 음전·건반 제어 | 관 공명 및 발진 모델 |
| 전자악기 | 발진기, 필터, 엔벌로프, 증폭 및 회로 상호작용 | DSP 및 가상 아날로그 회로 모델 |
| 보컬 (MVS) | 성문, 기도, 호흡, 조음, 운율과 가사 | 기존 CHIMERA 계열 FDTD 및 성문 소스; 신규 발성 연구 |

모든 악기에 동일한 FDTD나 완전한 3D 유체·구조 해석을 강제하지 않는다. 대역폭, 안정성, 연주감, CPU 예산 및 구현 난이도를 고려하여 목적에 맞는 축약 물리 모델을 선택한다. 전자악기는 생체나 기계 진동에 한정하지 않고 전자 회로와 DSP를 모델링한다.

현의 기본 주파수의 이상적 근사: f = (1/(2L)) * sqrt(T/mu), L은 길이, T는 장력, mu는 선밀도. 실제 현의 강성, 접촉, 몸체 결합 등은 별도 모델이 필요하다. 사용자가 재질과 형상을 바꾸더라도 모든 값이 실재 악기의 측정값인 것처럼 표현하지 않는다.

## 3. 악보와 연주를 분리하는 공통 시스템

~~~mermaid
flowchart TD
 A[사용자 악보 / MIDI / MusicXML] --> B[공통 스코어 및 시간축]
 X[선택적 AI 작곡·편곡] --> B
 B --> C[연주 해석 및 제스처]
 Y[사용자 수정 / 선택적 AI 지휘] --> C
 C --> D[현악기·관악기·타악기·건반]
 C --> E[MVS 보컬 및 합창]
 D --> F[독립 음원 트랙]
 E --> F
 F --> G[믹서 및 가상 공연장]
 G --> H[실시간 재생 또는 오프라인 렌더]
 F --> I[Stem WAV]
~~~

공통 score는 템포·박자·조성·트랙·음표·강세·아티큘레이션을 표현한다. MIDI와 MusicXML 가져오기를 기본으로 하고, 가사는 기존 MVS 음절 계약과 연결한다. 각 악기에 note-on/off, velocity, pitch bend, expression, articulation, breath/bow/strike 등의 의미 있는 제스처를 보낸다. 악기마다 지원하는 제스처는 capability 목록으로 명시하며, 지원하지 않는 제어는 조용히 잘못 해석하지 않는다.

AI 편곡은 악기 배치, 화성, 리듬, 음역과 표현을 제안한다. 지휘 계층은 템포 루바토, 프레이징, 강약, 합주 타이밍과 균형을 제어한다. 최종 스코어와 제스처는 사용자가 검수 및 편집할 수 있어야 한다. AI가 생성한 악보도 고정된 스코어와 시드로 저장할 수 있다. 단, AI 모델 자체의 결정론을 가정하지 않는다.

## 4. 공통 악기 설계 계약 (초안)

~~~json
{
  "schemaVersion": 1,
  "instrumentId": "experimental-bowed-string-01",
  "family": "bowed-string",
  "model": "waveguide-modal",
  "parameters": {
    "stringLengthM": 0.33,
    "tensionN": 50,
    "linearDensityKgPerM": 0.0005,
    "bodyPreset": "synthetic-wood-body"
  },
  "capabilities": ["note", "velocity", "bow-pressure", "bow-position", "vibrato"],
  "provenance": "synthetic-example",
  "seed": 1972
}
~~~

위 값은 동작을 설명하기 위한 임의의 설계 예시이며 특정 실재 바이올린의 측정값이나 구현된 API가 아니다. 물리량은 SI 단위를 기본으로 하고 기존 CHIMERA의 CGS 기도 모델과는 명시적인 단위 변환 경계에서 연결한다. 파라미터 범위, 유한성, 안정성, 음역, 모델 버전 및 출처를 확인하고, 실행 전 메모리와 상태를 준비한다.

각 음원은 공통 샘플 클록으로 구동하되 독립적인 악기 인스턴스와 상태를 가진다. 연주 중에는 필요한 제어 변화만 보내고, 구조적 변경은 안전한 시점에 적용한다. 재현에 필요한 스코어, 모델 버전, 프리셋, 시드와 출력 포맷을 프로젝트 파일에 기록한다. 플랫폼 부동소수점 차이는 별도 검증한다.

## 5. IRIS Virtual Philharmonic Orchestra

가상의 공연장을 만들고 현악·목관·금관·타악 섹션 및 MVS 보컬/합창을 배치한다. 같은 시스템의 작은 편성으로 피아노·보컬 듀엣, 실내악, 팝 밴드, 기타·베이스·드럼 편성 등을 구성한다. 연주자별 음색과 미세 타이밍 편차를 시드 기반으로 제어하여 모두 같은 파형이 겹치는 문제를 피한다.

공연장 모델은 위치·거리·방향성·초기 반사·잔향·관객 흡음 등을 표현한다. 첫 단계는 알고리즘 리버브 및 패닝, 다음 단계는 권한 있는 임펄스 응답 또는 기하 음향 연구로 확장한다. 3D 공연장이나 악기 애니메이션은 선택적이며, 사운드 모델과 단순 시각적 연출의 차이를 명확히 표시한다.

라이브 모드는 CPU 예산에 따라 음원 수와 모델 복잡도를 제한한다. 대규모 오케스트라나 고양이 100마리 합창은 오프라인 렌더부터 검증한다. 각 트랙의 독립 WAV, 혼합 WAV, 프로젝트 파일을 출력하고 음량·팬·잔향·마스터 리미터를 편집할 수 있게 한다.

## 6. 현실에 없는 악기 연구

- 유리 몸체를 가진 가상 바이올린: 재질에 따른 강성·감쇠·공명 비교.
- 길이 20m의 가상 플루트: 긴 공기 기둥과 실용 음역 탐색. 실제 연주 가능성은 별도로 평가한다.
- 인간 성문과 첼로 몸체 공명 결합: 소스-공명기 결합을 실험하는 창작 악기.
- 골골송 기반 오르간 음색: 저주파 발성 소스와 공명관의 조합.
- 인간과 가상 생물 합창: 다양한 발성 모델이 같은 악보를 노래하는 편성.

실재하지 않는 물성이나 과장된 형상은 fantasy/experimental로 구분하며, 수치 안정성과 청각적 안전을 우선한다. 가상 악기라는 표현은 완전한 실제 물리의 재현을 보장하지 않는다.

## 7. 구현 경계와 후보 모듈

MVS의 핵심은 발성 연구를 유지한다. 악기 연구는 독립 모듈(예: 신규 Rust crate mvs-instruments)로 검토하며 기존 chimera crate의 human/creature 경로를 불필요하게 변경하지 않는다. 공통 score/transport/mixer 계층만 연결한다. 후보 모듈은 instruments, performance, ensemble, room, render 등이며 실제 경로와 패키지명은 추후 결정한다.

실시간 오디오 콜백에서 할당·잠금·I/O·AI 호출을 하지 않고, AI 해석은 사전 계획 또는 안전한 외부 제어 계층에서 처리한다. 먼저 CLI/오프라인 렌더로 모델을 검증하고 WASM/AudioWorklet 경로로 확장한다. 기존 [Rust 엔진 계약](../rust-engine.md)을 참고하되 별도 악기 엔진의 계약도 명시한다.

## 8. 연구 로드맵

| 단계 | 제안 산출물 | 검증 |
|---|---|---|
| I0 | 공통 악보/연주 이벤트 규격 | 기존 MVS 가창 시간축과 호환 |
| I1 | 발현 현악기와 모달 타악기 최소 PoC | 음정·감쇠·안정성·재현성 |
| I2 | 건반·활현악·관악 개별 모델 | 아티큘레이션, 음역, 음색 비교 |
| I3 | 소규모 팝 밴드/실내악 + MVS 보컬 | 트랙 동기화, stem 출력 및 혼합 |
| I4 | 가상 오케스트라 및 공연장 | 대편성 CPU 비용, 공간감, 드리프트 |
| I5 | 가상 지휘/AI 편곡 및 신종 악기 편집 | 사용자 검수, 제어 가능성, 재현성 |

각 단계는 일정 확약이 아니다. 음색·공명·F0·attack/decay, 연주 표현, CPU 및 메모리, NaN/Inf와 클리핑, 재생 시간축, 블록 크기 독립성, 장시간 안정성을 측정한다. 물리 정확도와 음악적 유용성은 별도 지표로 평가한다. 참고 음원과 악보는 이용권한을 확인하고, 저장소에는 자체 창작 또는 허용된 시험 자료만 넣는다.

첫 실험은 짧은 자체 제작 '먀용' 악보에 물리 합성 현악기 또는 타악기 하나를 더하는 것이다. 고양이의 목소리로 시작한 연구가 작은 합주를 거쳐 가상 공연장의 음악으로 이어지는 과정을 기록한다. 🐾
